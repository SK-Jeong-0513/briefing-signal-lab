# 주간 통합 브리핑 메일러 (Google Apps Script)

무료 구독자에게 **기술·금융·경제 3개 카테고리를 한 통**으로 발송하고, 이메일 링크로 선호도/수신거부를 카테고리별 시트에 반영하는 메일러.

- **경로:** Google Apps Script. 사이트 호스팅과 독립.
- **발송:** 월요일 09:00 `sendWeekly()` 트리거(구독자당 1통, 구독한 카테고리·분야 섹션만).
- **위치:** 배포 안 됨(사이트는 `public/`만 서빙). 버전관리·복사용 원본.

## 시트 구조 (응답 1 + 선호도 3)

| 탭 | 역할 | 발송기 |
|---|---|---|
| **설문지 응답 시트1** (`RESP_SHEET`) | 신원·동의 원천. 최초 1회 가입 기록. | **읽기 전용** (`이메일 주소`, `메일 수신 동의`, `관심 키워드`) |
| **관심분야(기술)** | 기술 구독 상태 | 읽기/쓰기 |
| **관심분야(금융)** | 금융 구독 상태 | 읽기/쓰기 |
| **관심분야(경제)** | 경제 구독 상태 | 읽기/쓰기 |

선호도 시트 스키마(자동 생성): `이메일 | 관심 분야 | 상태 | 갱신`
- 관심 분야 = 콤마구분 분야 라벨. 기술=`AI 인프라, 반도체 공급망` / 금융=`국내 증시, 미국 증시` / 경제=`경제 매크로`.
- 상태 = `구독` / `수신거부`.

## 설치 / 갱신 시 주의

1. 응답 시트에서 **확장 프로그램 → Apps Script** → `Code.gs` 붙여넣기(독립 프로젝트면 `CFG.SHEET_ID`).
2. **CFG.SALT는 이전에 설정한 값 그대로 유지** — 바꾸면 이미 보낸 메일의 링크 토큰이 깨집니다.
3. **doGet 코드가 바뀌었으므로 웹앱 재배포 필요:** 배포 → **배포 관리 → ✏️(편집) → 버전: 새 버전 → 배포.** URL은 그대로 유지되니 `CFG.WEBAPP_URL`도 그대로.
4. 3개 선호도 탭(`관심분야(기술)/(금융)/(경제)`)이 존재하는지 확인(헤더는 자동 생성).
5. `sendWeekly` 실행 → `TEST_MODE=true`면 나에게만 1통(미리보기, 원장 변경 없음) → OK면 `false`로 바꾸고 `createWeeklyTriggers()` 1회 실행.

## 발송 로직

- 응답 시트에서 `이메일 주소` + `메일 수신 동의`(O) 필터. 중복 이메일 1건만.
- 각 구독자에 대해 **3개 카테고리 각각** 선호도 시트 조회:
  - 있으면 → 그 분야만. `상태=수신거부`면 그 카테고리 제외.
  - 없으면(최초) → 그 카테고리 가동 분야 전체 발송 + 시트에 행 자동 생성(seed).
- 구독 섹션이 하나도 없으면 발송 건너뜀.
- 이메일 링크: **분야 토글**(카테고리·분야별) + **수신거부**(전역, 3개 시트 모두 `수신거부`).

## 매주 발송

- 콘텐츠는 `BSL_market/주간-발행항목` rev.1 스냅샷을 사용한다. 코드의 정적 `CATS[].issues`는 주간 발송 소스가 아니다.
- 월요일 09:00 트리거가 `sendWeekly()`를 실행하며, 실패 후 재실행은 성공 수신자를 제외한다.

## 개인정보/발송 규칙

- 이메일은 링크에 넣지 않음(해시 토큰만). 수신거부 필수(정보통신망법).
- 발송 한도 GmailApp ~100통/일. 대량·정식은 도메인 인증 ESP로 이관.
- 이메일은 KO. 종목·자산은 관찰 대상으로만 명시, 매수·매도 권유 없음.

## 자동 주간 발송 (2026-07-27 설계)

주간 메일은 코드에 고정된 `CATS[].issues`가 아니라 `BSL_market`의 발행 원장과 발행항목을 읽는다.

- 월요일 09:00 KST 고정 발송 (2026-08-03 화 20:00 → 월 09:00 이동)
- `published` 상태이며 발행항목이 1건 이상인 호만 대상
- 호·리비전·수신자 해시별 성공 로그가 있으면 재발송하지 않음
- 부분 실패 재시도는 실패 수신자만 대상
- 웹판 `rev.2+` 업데이트는 이메일 재발송하지 않음
- 0건은 `skipped`

Apps Script에는 `MARKET_SHEET_ID`와 운영자 알림 이메일 설정이 필요하다. 기존 `sendDailyMarket()`과 `createDailyTrigger()`는 별도 경로로 유지한다.

배포 순서:

1. `CFG.MARKET_SHEET_ID`에 BSL_market ID를 설정하고 Apps Script 속성 `WEEKLY_CRON_TOKEN`에 긴 임의 토큰을 저장한다.
2. `admin/`으로 `주간-발행`·`주간-발행항목`·`주간-발송로그` 탭을 먼저 만든다.
3. Apps Script에 `mailer/Code.gs`를 다시 붙여넣고 `TEST_MODE=true`로 `sendWeekly()` 미리보기 1건을 확인한다. 테스트 모드는 원장과 발송 로그를 변경하지 않는다.
4. `TEST_MODE=false`로 바꾸고 웹앱을 새 버전으로 재배포한다. GitHub Secret `WEEKLY_MAILER_URL`에는 이 웹앱 URL, `WEEKLY_MAILER_TOKEN`에는 위 스크립트 속성과 같은 값을 넣는다. `.github/workflows/weekly-send.yml`이 월요일 09:00 KST에 호출한다(지연 있음 — 정시성은 Apps Script 트리거가 담보).
5. `createWeeklyTriggers()`를 한 번 실행해 알림 3개(일 09:00·일 20:00·월 10:00)와 월요일 09:00 발송 트리거를 만든다. **정시 발송은 이 Apps Script 트리거가 담보한다** — GitHub Actions cron 은 상시 1~2시간 지연되므로 백스톱으로 본다. 먼저 도는 쪽이 발송하고 나중 쪽은 수신자 로그를 보고 중복을 막는다.
6. 기존 `createDailyTrigger()`는 그대로 유지한다. 다만 아래 "일일 시황 발송 시각" 변경 후에는 한 번 다시 실행해 동기화 트리거를 만든다.

## 일일 시황 발송 시각 (2026-07-27)

발송 시각은 코드가 아니라 **관리자 콘솔 설정**이다. 서머타임 등으로 적정 시각이 바뀌기 때문이다.

- 값: `BSL_market`의 `settings` 탭 `daily_send_time`, `HH:MM` KST. 관리자 콘솔 ⑤ 탭에서 지정한다.
- 미설정·형식 오류는 `CFG.DAILY_SEND_TIME`(기본 `07:40`)로 폴백하고 로그를 남긴다. 시트 조회 실패도 마찬가지(fail-open).
- `applyDailySchedule()`이 설정 시각으로 발송 트리거를 재생성한다(멱등 — 여러 번 실행해도 트리거는 1개).
- `syncDailySchedule()`이 매일 새벽 03:00에 돌며 설정이 바뀌었거나 트리거가 사라졌으면 재생성한다. **콘솔에서 시각을 바꾸면 다음 날부터 자동 반영**된다.
- `createDailyTrigger()`는 설치용이다. 발송 트리거 + 새벽 동기화 트리거를 함께 만든다.

⚠️ **Apps Script 시간 트리거는 지정 시각 ±15분 오차가 있다**(정확한 시각 지정 불가). 종전에는 `atHour(8)`만 있고 `nearMinute()`가 없어 08:00~09:00 사이 **임의 시각**에 실행됐고, 그래서 KRX 장전 단일가(08:30) 이후에 도착하는 일이 있었다. 목표 도착 시각보다 여유를 두고 지정할 것. 텔레그램 `장전` 요약 생성(07:00 KST, 별도 레포)보다 뒤여야 그날 상세 본문이 담긴다.

## 주요 시장 지표 블록 (2026-07-31 갱신)

일일 메일 상단에 지표 21개를 2열 11행으로 넣는다. 표시 문자열은 `scripts/fetch_dashboard.py`가 `public/assets/data/quotes.json`에 미리 만들어 두고, 메일러는 `quotes_()`로 **한 번 읽어 그리기만** 한다(메일러는 수동 붙여넣기 배포라 티커·포맷 변경이 여기 닿지 않게 하기 위함).

- `.github/workflows/daily-quotes.yml`이 **매일** 06:10 KST에 `--quotes-only`로 지표만 먼저 갱신한다.
  기존 전체 대시보드 파이프와 분리해 메일 발송(`settings.daily_send_time`, 현재 07:20 KST)보다
  앞서 배포될 여유를 둔다. **평일이 아니라 매일인 이유:** 일일 메일이 `everyDays(1)`로 주말에도
  나가는데 주말에 갱신이 없으면 `briefing_date`가 금요일에 머물러 블록이 통째로 생략된다
  (2026-08-08 토·08-09 일 실제 누락). 요일을 다시 좁히지 말 것.
- `briefing_date`는 **한국 기준 브리핑 날짜**, `asof`는 **미국장 마감 기준일**이다. 메일에는 `MM-DD 아침 기준 · 미 증시 MM-DD 마감`으로 둘을 함께 표시한다.
- `quotes_()`는 `?v=현재시각`을 붙여 GitHub Pages의 최대 10분 캐시를 우회한다.
- `briefing_date`가 한국 기준 당일이 아니면 전일 스냅샷을 사용하지 않고 **지표 블록만 생략**한다.
- 실패·낡음은 전부 **블록만 생략**하고 메일은 정상 발송한다. `asof`가 `QUOTES_STALE_DAYS`(5일)를 넘으면 생략 — 연휴 3~4일은 통과하고 파이프 고장만 잡는다.
- `asof`는 발송일이 아니라 **어느 장의 숫자인가**다. 월요일 아침에 금요일 마감이 찍히는 게 정상.
- 티커·라벨·소수자리를 바꾸려면 `fetch_dashboard.py`의 `QUOTES`만 고친다. 메일러는 건드리지 않는다.
- **발송 50분 전 `preflightQuotes()`가 신선도를 먼저 본다**(2026-08-27 추가). 낡았으면 GitHub
  `workflow_dispatch`로 `daily-quotes.yml`을 직접 발화하고, 20초 간격 6회까지 반영을 기다린다.
  발화 주체가 GitHub 예약 크론이 아니라 Apps Script 트리거라 그날 예약분이 통째로 밀려도 산다.
- **블록이 실제로 빠지면 운영자에게 메일이 간다**(`alertQuotesMissing_`). 종전에는 `Logger.log`만
  남아 아무도 보지 않았고, 두 번 다 구독자가 메일을 읽고 나서야 발견됐다.

### 운영 Apps Script 반영

저장소를 푸시해도 운영 Apps Script의 `Code.gs`는 자동 갱신되지 않는다. 저장소 사본의 `CFG`에는 플레이스홀더가 있으므로 **파일 전체를 붙여넣지 않는다.**

1. 메일러 연결 Google Sheet에서 **확장 프로그램 → Apps Script → Code.gs**를 연다.
2. 현재 운영 코드를 프로젝트 외부에 백업한다. 같은 Apps Script 프로젝트 안에 `.gs` 복사본을 만들면 함수명이 중복되므로 피한다.
3. 운영본의 실제 `CFG` 값(`TEST_MODE`, `WEBAPP_URL`, `SALT`, `SHEET_ID`, `MARKET_SHEET_ID` 등)은 그대로 둔다.
4. **저장소 `mailer/Code.gs`의 51행(`// ===== 카테고리 정의 …`)부터 파일 끝까지**를 복사해,
   운영본의 같은 구간(= `CFG` 아래 전체)과 통째로 교체한다. `CFG` 는 건드리지 않는다.
   - 2026-08-27 에 운영본을 받아 대조한 결과 **51행 이후가 MD5까지 저장소와 동일**했다.
     콘솔에서 손으로 고친 흔적이 없으므로 통짜 교체가 블록별로 붙이는 것보다 안전하다
     (붙여넣기 누락·중복 여지가 없다).
   - **다시 할 때도 먼저 대조할 것.** 운영본 전체를 텍스트로 저장한 뒤
     `python -c "import io,hashlib; ..."` 로 저장소의 51행 이후와 해시를 비교한다.
     다르면 그 차이가 콘솔에서만 고친 내용이므로, 통짜 교체하면 조용히 되돌아간다.
   - 새 설정은 `CFG` 가 아니라 지표 블록 상단의 `QUOTES_*` 상수와 스크립트 속성에 있다.
5. **스크립트 속성에 PAT를 넣는다** — 프로젝트 설정 → 스크립트 속성 → 속성 추가.
   - 키: `GH_DISPATCH_TOKEN`
   - 값: GitHub 파인그레인드 PAT (Repository access = `briefing-signal-lab` 하나만,
     Repository permissions → **Actions: Read and write**. `Metadata: Read-only` 는 자동으로 붙는다.
     `Contents` 는 주지 않는다 — 커밋은 워크플로 안의 `GITHUB_TOKEN` 이 한다)
   - 만료일을 짧게 잡으면 갱신을 잊는 순간 사전 점검만 죽는다. 만료 시
     `preflightQuotes()` 가 발화에 실패하며 **운영자 메일로 알린다**(무증상으로 죽지는 않는다).
6. **`applyDailySchedule()` 을 1회 실행한다.** 사전 점검 트리거는 이 함수가 만든다 —
   안 돌리면 코드만 들어가고 트리거가 없어 아무 일도 일어나지 않는다.
   실행 로그에 `... KST sendDailyMarket (±15분) · 06:30 KST preflightQuotes` 가 찍히면 정상.
7. 저장한다. 이번 변경은 시간 트리거가 실행하는 최신 저장 코드를 바꾸는 것이므로 **웹 앱 재배포는 필요 없다.**
   > ⚠️ 습관적으로 **"배포 → 새 배포"를 누르지 말 것.** 새 `/exec` URL 이 생겨 `CFG.WEBAPP_URL` 과
   > 이미 발송된 메일 속 수신거부 링크가 가리키는 배포본이 갈라진다. 웹앱 코드를 실제로 고칠 일이
   > 생기면 "배포 관리 → 편집(연필) → 버전: 새 버전" 으로 **같은 URL 을 유지**하며 올린다.

### 토큰이 실제로 먹는지 확인

`preflightQuotes()` 는 데이터가 최신이면 발화까지 가지 않아 **토큰을 한 번도 쓰지 않는다.**
아래를 임시로 붙여 실행해 `true` 를 확인한 뒤 지운다(무해하다 — 크론이 하는 일과 같고,
내용이 같으면 커밋도 안 한다).

```javascript
function testDispatch() {          // ⚠️ 이름 끝에 _ 를 붙이면 실행 드롭다운에 안 나온다
  Logger.log("발화 결과: " + dispatchQuotes_());
}
```

`false` 면 로그의 `발화 HTTP ###` 를 본다 — **403** 권한(Actions: Read and write)·만료,
**404** 레포 선택 오류, **401** 토큰 값이 잘렸거나 공백 혼입.
성공하면 GitHub Actions 에 `workflow_dispatch` 실행이 새로 뜬다(2026-08-27 run `33029384017` 로 확인).

### 사전 점검 동작 확인

`preflightQuotes()`를 직접 실행하고 로그만 본다. **부작용이 없다** — 최신이면 아무것도 하지 않고,
낡았을 때만 워크플로를 발화한다(메일 발송 코드가 아니다).

| 로그 | 뜻 |
|---|---|
| `[지표·사전점검] 2026-08-27 최신 — 조치 없음` | 정상. 평소 매일 이 줄만 나온다 |
| `... 워크플로 발화` → `복구 완료 — asof ...` | 크론이 늦었고 자가 복구됐다 |

## 이모지 등 비-BMP 문자 (2026-07-27)

**`GmailApp.sendEmail`은 서로게이트 쌍(astral) 문자를 깨뜨린다.** 시트 셀과 Apps Script 읽기까지는 정상인데(진단: `marketBody_()` 첫 줄 코드포인트 `U+D83D U+DCCC`) 수신 메일에서만 replacement 문자로 나온다. 한글은 BMP라 무사하고 이모지만 깨진다.

`mailSafe_()`가 **발송 직전** 평문·HTML 양쪽에서 `/[\uD800-\uDFFF]/g`를 제거한다. LLM이 만든 본문·제목 등 이모지 유입 경로가 여럿이라 각 생성 지점이 아니라 경계 한 곳에서 막는다. 텔레그램 프롬프트의 이모지는 그대로 둔다 — 텔레그램 메시지에서는 정상 표시된다.

**재발 방지: Apps Script 메일에 astral 문자를 넣지 말 것.**

> 2026-08-16: `mailSafe_()` 호출을 각 호출부에서 `sendMail_()` 래퍼 한 곳으로 모았다.
> 발송 지점이 늘어도(스페셜 리포트) 빠뜨릴 수 없고, 예전에 안 감쌌던 **제목**까지 함께 막힌다.

## 재구독 복구 (2026-08-03)

수신거부한 사람이 구독 폼으로 다시 신청해도 `관심분야` 시트 상태가 `수신거부`로 남아 영구 차단되던 문제를 해결했다. 구독 폼은 **`메일 수신 동의` 체크가 필수**라 재제출을 새로운 명시적 동의로 본다.

- `syncResubscribes_()`가 **발송 직전 한 번** 돌며 재신청자를 `구독`으로 되돌린다. `unsubSet_()`과 주간 루프는 그대로 읽기만 하므로 차단 로직 자체는 바뀌지 않았다.
- 판정: **그 이메일의 가장 최근 응답 시각 > 수신거부 시각**이면 복구.
  - ⚠️ 발송 루프는 `seen[email]`로 **첫(=가장 오래된) 행**만 취하므로, `respLatestTs_()`가 최댓값을 따로 구한다.
- **판별이 불가능하면 수신거부를 유지한다**(안전 쪽). 타임스탬프 열 없음 · 파싱 실패 · **동률** 전부 해당.
- 시각 도입 전 행은 `갱신`에 날짜만 있어 `unsubTime_()`이 **그날 끝(23:59:59)**으로 해석한다 — 같은 날 먼저 낸 응답이 해지보다 나중으로 오판돼 "수신거부했는데 또 온다"가 되는 것을 막는다.
- 앞으로는 `prefUpsert_()`가 `갱신`에 **날짜+시각**(`yyyy-MM-dd HH:mm:ss`)을 저장해 같은 날 해지→재신청도 구분된다.
- 분야를 모두 끈 뒤 해지한 경우는 빈 분야로 되살리면 메일이 안 가므로 **가동 분야 전체**로 복원한다.
- 타임스탬프 열은 `타임스탬프`/`Timestamp`를 찾고 없으면 1열로 폴백한다(폼 시트는 1열이 항상 타임스탬프). 그래도 못 읽으면 복구 없이 현행 동작을 유지한다.

검증: `tests/test_resubscribe.js` — 시각 해석 · 판정 경계(동률·옛 행 같은 날·파싱 실패) · 최신 응답 선택 · 시트 쓰기 · 배선 순서.

### 운영 Apps Script 반영

파일 전체를 붙여넣지 않는다(저장소 사본의 `CFG`는 플레이스홀더). 운영본의 `CFG`는 그대로 두고 아래 4곳만 교체·추가한다. 행 번호는 저장소 `mailer/Code.gs` 기준.

1. **`prefMap_()` 교체** — 155~165행. (`갱신` 열과 원래 대소문자 이메일을 함께 읽도록 바뀜)
2. **`prefUpsert_()` 교체** — 166~179행. (`갱신`을 날짜+시각으로 저장)
3. **재구독 복구 블록 추가** — **480~577행**을 통째로 복사해 `// 수신거부(모든 pref 시트 상태=수신거부)한 이메일 집합.` **바로 앞에** 붙여넣는다. 끝의 운영자 진단 `checkResubscribe()`(556~577행)까지 포함한다 — 임시 함수가 아니라 상시 도구다.
   - 시작: `// ===== 재구독 복구 =====`
   - 끝: `syncResubscribes_()`의 닫는 중괄호 `}`
4. **호출 1줄씩 추가** — `sendDailyMarket()`의 `var unsub = unsubSet_();` 바로 위, `sendWeeklyUnlocked_()`의 `var maps = {};` 바로 위에 각각:
   ```javascript
   syncResubscribes_();
   ```

⚠️ **웹앱 재배포가 필요하다.** `doGet`(수신거부·분야 토글)이 `prefUpsert_()`를 쓰고 `doPost`가 `sendWeekly()`를 호출하는데, 웹앱은 시간 트리거와 달리 **배포된 버전**으로 실행된다. 배포 → 배포 관리 → ✏️ → 버전: 새 버전 → 배포. URL은 유지되므로 `CFG.WEBAPP_URL`과 GitHub Secret은 그대로.

### 배포 후 확인

⚠️ **`TEST_MODE`는 재구독 복구를 막지 못한다.** `TEST_MODE`는 메일 수신자만 운영자로 돌리는 스위치이고, `syncResubscribes_()`는 그와 무관하게 시트에 쓴다. 그래서 **읽기 전용 진단을 먼저** 돌린다.

1. **`checkResubscribe()`** 를 실행해 **누가 복구 대상인지만** 확인한다(아무것도 바꾸지 않는다). 위 3번 블록에 포함돼 있으므로 따로 붙여넣을 필요가 없다.

⚠️ **임시 함수를 만들 때 이름 끝에 `_`를 붙이지 말 것.** Apps Script는 `_`로 끝나는 함수를 private으로 취급해 **실행 드롭다운에 표시하지 않는다**(트리거·`google.script.run`도 불가). 같은 이유로 `syncResubscribes_()`도 직접 고를 수 없어, 강제 실행이 필요하면 아래 래퍼를 임시로 붙였다가 지운다. 함수 **안에서** `_` 함수를 호출하는 것은 제한되지 않는다.

```javascript
// 임시 — 발송을 기다리지 않고 지금 복구를 반영하고 싶을 때. 확인 후 삭제한다.
function runResubscribe() {
  Logger.log("[재구독] 복구 " + syncResubscribes_() + "건");
}
```

- `응답 시각을 읽은 이메일: 0명` → 타임스탬프 열을 못 찾은 것. 응답 시트 1열을 확인한다.
- `수신거부 상태 0명` → 지금 차단된 사람이 없다는 뜻이지 고장이 아니다.

2. `runResubscribe()`를 실행해 실제로 반영한다 — 로그 `[재구독] 수신거부 해제 N건`, 시트의 `상태`가 `구독`으로 바뀐다.
3. `TEST_MODE=true`로 `sendDailyMarket()` 1회 — 운영자에게 미리보기 1통. 그날 `시장-일일`에 행이 없으면 **조기 return** 되어 `syncResubscribes_()`까지 가지 않는다. 첫 발송 후 `break` 하므로 복구된 사람이 첫 대상이 아니면 그 사람 메일은 오지 않는다(배선 확인용이지 복구 검증용이 아니다).
4. `TEST_MODE=false`로 되돌리고 임시 함수를 삭제한다. **`checkResubscribe()`는 남긴다** — "구독했는데 메일이 안 와요" 문의 때 쓰는 상시 진단이다.

`TEST_MODE=false`에서 `sendDailyMarket()`을 진단용으로 실행하지 말 것 — 전체 발송된다.
